# Architecture

IT Hub ERP is **one Next.js application** that serves both the web pages and the API, backed by one
**PostgreSQL** database. Many companies ("organizations") share the same app and database; every
business record belongs to exactly one organization.

## Tech stack

| Concern       | Choice                                        | Where                                       |
| ------------- | --------------------------------------------- | ------------------------------------------- |
| Framework     | Next.js 16 (App Router, React 19, Turbopack)  | `src/app`                                   |
| Language      | TypeScript 6 (strict)                         | `tsconfig.json`                             |
| Styling       | Tailwind CSS 4                                | `src/app/globals.css`, `postcss.config.mjs` |
| UI components | shadcn/ui (Radix primitives, "Nova" preset)   | `src/components/ui`, `components.json`      |
| Icons         | Lucide                                        | `lucide-react`                              |
| Forms         | React Hook Form + Zod resolver                | e.g. `src/features/auth/login-form.tsx`     |
| Validation    | Zod 4                                         | `src/lib/validation`, `src/lib/env`         |
| Database      | PostgreSQL via Prisma 7 (driver adapter `pg`) | `prisma/`, `src/lib/db`                     |
| Unit/UI tests | Vitest + Testing Library (jsdom)              | `tests/unit`, `vitest.config.mts`           |
| E2E tests     | Playwright                                    | `tests/e2e`, `playwright.config.ts`         |
| Lint / format | ESLint 9 (Next config) + Prettier             | `eslint.config.mjs`, `.prettierrc.json`     |

## Folder structure

```
src/
  app/                   Routes. (auth)/ = public pages, (dashboard)/ = signed-in pages, api/ = REST endpoints
  components/
    ui/                  shadcn/ui primitives (generated by the shadcn CLI — restyle, don't fork)
    shared/              App-wide building blocks: PageHeader, Loading/Empty/Error states, ConfirmButton
    layout/              App shell (sidebar)
    forms/ tables/ charts/   Reserved for reusable form, table and chart components
  features/<module>/     UI that belongs to one module (e.g. features/auth/login-form.tsx)
  server/
    actions/             Server Actions called from forms
    services/            Business rules, transactions, audit logging
    repositories/        Database queries (Prisma), always scoped by organizationId
  lib/                   Infrastructure: auth, db, env, permissions, tenant, validation, audit, utils
  config/                Static app config (site name, navigation)
  types/                 Shared TypeScript types
  generated/prisma/      Prisma client — generated on `npm install`, not committed
  instrumentation.ts     Runs once at server start: validates environment variables
```

## How a request flows

```
Browser ──► page / form ──► server action ─┐
                                           ├──► service ──► repository ──► Prisma ──► PostgreSQL
API client ──► src/app/api/* route ────────┘        │
                                                    └──► audit log (same transaction)
```

1. **Route handlers and server actions are thin:** validate input with Zod → check login and
   permission (`requirePermission`) → call a service.
2. **Services** hold business rules. They receive a `TenantContext` and pass `ctx.organizationId`
   to repositories. Mutations write an `AuditLog` row in the same database transaction.
3. **Repositories** are the only code that queries business data with Prisma. A repository function
   without an `organizationId` argument is a bug (it could leak another company's data).
4. **UI components never touch the database.** ESLint blocks `@/lib/db`, `@/generated/prisma` and
   repository imports inside `src/components` and `src/features`.

Authentication is a service too (`auth.service.ts`): the login form's server action and
`POST /api/auth/login` share the same credential check.

The full rule set every contributor and AI agent must follow is in [`AGENTS.md`](../AGENTS.md).
Several of those rules are enforced automatically by ESLint (no `any`, no `@ts-ignore`, no empty
`catch`, no database access from UI).

## Configuration (environment variables)

- All variables are listed and explained in `.env.example`.
- `src/lib/env/schema.ts` defines them with Zod. `getServerEnv()` (in `src/lib/env`) validates them
  on first use and `src/instrumentation.ts` calls it when the server starts, so a missing or
  malformed variable stops the app immediately with a list of what is wrong (values are never printed).
- `next build` also validates them, so a misconfigured deployment fails at build time, not in front of users.
- Server-only modules (`@/lib/env`, `@/lib/db`) import `server-only`, which makes it a build error to
  import them from browser code — secrets cannot leak into the client bundle.

## UI system

- Design tokens (colors, radius) are CSS variables in `src/app/globals.css`; Tailwind utilities
  such as `bg-background` and `text-muted-foreground` read them. Dark-mode tokens exist under `.dark`;
  the toggle arrives with the app shell in phase 01.
- Add shadcn components with `npx shadcn@latest add <name>`; they land in `src/components/ui`.
- Forms use React Hook Form with `zodResolver(schema)` for instant feedback, and the **same Zod
  schema is re-checked on the server**, because browser validation can be bypassed.

### Required UI states

Every module page must handle loading, empty, error and success states, and every destructive
action must be confirmed. Use the shared components in `src/components/shared`:

| Component        | Use                                                                                  |
| ---------------- | ------------------------------------------------------------------------------------ |
| `LoadingState`   | Suspense/loading fallback (`(dashboard)/loading.tsx` covers route transitions)       |
| `EmptyState`     | A list with no records, with an optional call to action                              |
| `ErrorState`     | Recoverable errors, with retry (`(dashboard)/error.tsx` is the route-level boundary) |
| `SuccessMessage` | Confirmation after a mutation                                                        |
| `ConfirmButton`  | Required wrapper for delete/void/other destructive actions                           |

## Testing

| Kind        | Tool                      | Location                   | Command            |
| ----------- | ------------------------- | -------------------------- | ------------------ |
| Unit        | Vitest (Node)             | `tests/unit/**/*.test.ts`  | `npm run test`     |
| Component   | Vitest + Testing Library  | `tests/unit/**/*.test.tsx` | `npm run test`     |
| Integration | Vitest (reserved)         | `tests/integration/`       | `npm run test`     |
| End-to-end  | Playwright (real browser) | `tests/e2e/*.spec.ts`      | `npm run test:e2e` |

## Reference module

`customers` is the fully wired reference implementation:
`api/customers/route.ts` → `customer.service.ts` → `customer.repository.ts`.
New modules copy this shape. The other API folders are permission-checked stubs that return `501`
until their phase is implemented.
